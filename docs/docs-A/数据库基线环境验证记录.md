## 2. 初始化脚本联动

`db/init/00_run_sql_assets.sh` 已通过 PostgreSQL Docker 初始化入口执行。

日志中可见：

```text

[TPC CommerceInsight] Loading development sample data

```

执行顺序：

```text

```


## 3. psql 连接验证

容器内连接命令：

```powershell
docker exec -i tpc-commerce-postgres psql -U tpc_admin -d tpc_commerce
```

已验证：

1. 当前数据库为 `tpc_commerce`。
2. 当前连接用户为 `tpc_admin`。

4. 样例数据已加载，`orders`、`lineitem`、`stock`、`app_user` 均可查询。
5. `trg_stock_quantity_change` 与 `trg_import_task_audit` 已存在。
6. `sp_analyze_region_revenue` 与 `sp_analyze_shipping_priority` 已存在并可调用。

## 4. SQL 资产联动验证

已在容器内执行：

```powershell
docker exec -i tpc-commerce-postgres psql -v ON_ERROR_STOP=1 -U tpc_admin -d tpc_commerce
```

验证内容：

1. `V5__tpch_queries.sql` 可加载，`tpch_q1`、`tpch_q5`、`tpch_q12`、`tpch_q14` 均可返回样例结果。
2. `V6__tpcc_transaction_sql.sql` 可加载，New-Order 与 Payment 的核心 `PREPARE` 模板可执行。
3. `V7__import_cleaning_rules.sql` 可加载，导入清洗相关 `PREPARE` 模板可创建。
4. `V12__explain_baseline.sql` 可手动执行，Q1/Q5/Q12/Q14 均输出执行计划。

库存触发器验证：

```text
BEGIN;
SELECT set_config('app.transaction_id', 'verify-rollback', true);
SELECT set_config('app.change_type', 'new_order', true);
EXECUTE tpcc_no_update_stock(1, 1001, 3);
SELECT warehouse_id, item_id, old_quantity, new_quantity, change_quantity, change_type, related_transaction_id
FROM stock_change_log
WHERE related_transaction_id = 'verify-rollback';
ROLLBACK;
```

结果：

```text
stock_change_log 记录 old_quantity=100、new_quantity=97、change_quantity=-3。
ROLLBACK 后 stock.s_quantity 恢复为 100，验证过程未污染样例数据。
```
