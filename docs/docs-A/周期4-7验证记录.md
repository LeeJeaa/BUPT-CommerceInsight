## 3. 关键验证结果

### 3.1 New-Order

验证动作：

```text
设置 app.transaction_id = NO-TEST-0001
执行订单号递增
插入 tpcc_orders
插入 new_order
扣减 stock
插入 order_line
写 transaction_log
```

结果：

```text
stock.s_quantity 从 100 变为 95。
stock_change_log 记录 old_quantity = 100，new_quantity = 95，change_quantity = -5。
related_transaction_id = NO-TEST-0001。
```

### 3.2 Payment

验证动作：

```text
支付金额 100.00。
更新 warehouse。
更新 district。
更新 tpcc_customer。
插入 history。
写 transaction_log。
```

结果：

```text
tpcc_customer.c_balance 从 620.25 变为 520.25。
tpcc_customer.c_ytd_payment 从 0.00 变为 100.00。
tpcc_customer.c_payment_cnt 从 0 变为 1。
```

### 3.3 导入审计和错误日志

验证动作：

```text
插入 import_task，status = running。
更新 import_task，status = success。
写入 import_error_log。
```

结果：

```text
status = running 时自动补全 started_at。
status = success 时自动补全 ended_at。
import_error_log 成功记录 o_totalprice = -1，reason = negative_amount。
```

### 3.4 存储过程

验证动作：

```sql
SELECT * FROM sp_analyze_region_revenue('ASIA', DATE '1994-01-01', DATE '1995-01-01');
SELECT * FROM sp_analyze_shipping_priority('MAIL', 'SHIP', DATE '1994-01-01', DATE '1995-01-01');
```

结果：

```text
sp_analyze_region_revenue 返回 CHINA 和 JAPAN 的收入。
sp_analyze_shipping_priority 返回 MAIL 和 SHIP 的高/低优先级统计。
```

### 3.5 索引和 EXPLAIN
