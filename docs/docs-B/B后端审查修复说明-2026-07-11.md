## 3. 数据导入修复

### 最终状态

`POST /api/import/tasks` 在处理与状态更新结束后重新查询 `getTask(taskId)`，不再返回处理前缓存的 `running` 对象。成功响应包含最终：

- `status`
- `totalRows`
- `successRows`
- `failedRows`
- `elapsedMs`
- `startedAt`
- `endedAt`

### 支持范围

系统演示导入只支持：

- `orders`
- `lineitem`

不提供 `partsupp` 半成品导入；其他表名返回 HTTP 400。mock、dev、prod 的范围保持一致。

### 逐行校验与错误日志

`orders` 校验订单主键、客户外键、订单状态、金额、日期、优先级和必填字段。

`lineitem` 校验订单、零件、供应商及零件供应关系，校验联合主键、数量、金额、折扣、税率、状态、日期和发运字段。

文件内重复、数据库主键冲突、外键缺失、格式错误和业务范围错误均写入 `import_error_log`。合法行继续批量写入；批次数据库异常会降级为逐行写入，并为失败行保留可读数据库错误。

## 4. 性能结果写入接口

新增管理员接口：

```text
POST /api/performance/results
```

请求 DTO 固定字段：

```text
testName
testType
threadCount
totalRequests
successCount
failCount
avgLatencyMs
maxLatencyMs
minLatencyMs
throughput
```

`testType` 只允许 `tpch`、`tpcc`。接口校验请求数守恒、非负数、数值精度以及 `minLatencyMs <= avgLatencyMs <= maxLatencyMs`。写入 `performance_result` 后，`GET /api/performance/results?testType=tpch|tpcc` 可立即读取最新结果。

## 5. 非法 JSON 状态码

全局异常处理器增加 `HttpMessageNotReadableException` 处理。截断 JSON、字段类型错误现在统一返回 HTTP 400，不再落入 500。
