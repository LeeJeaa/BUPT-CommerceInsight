# 产品需求文档

## 1. 产品定位

TPC CommerceInsight 是一个面向数据库课程设计的电商数据管理与 Benchmark 分析系统。系统围绕 TPC-H 分析查询、TPC-C 事务处理、批量导入清洗、索引优化和并发性能测试展开，最终服务于课程验收演示和设计报告。

## 2. 用户角色

| 角色 | 能力 |
|---|---|
| 管理员 | 用户审批、禁用用户、数据导入导出、查询分析、事务演示、性能结果查看 |
| 普通用户 | 登录后使用查询、分析、导出和可视化功能 |
| 未审批用户 | 只能注册和等待审批 |

## 3. 核心功能

| 模块 | 功能 | 负责人 |
|---|---|---|
| 登录注册 | 注册、登录、审批状态校验、角色区分 | B/C |
| 用户管理 | 用户列表、审批、禁用、删除 | B/C |
| 数据导入 | 页面上传文件、分批读取、清洗、错误日志、导入统计 | A/B/C |
| 数据导出 | 导出表数据或查询结果 | B/C |
| 业务查询 | 客户查询、订单收入查询、零部件供应查询 | A/B/C |
| TPC-H 分析 | Q1/Q5/Q12/Q14 查询、耗时、结果表格、图表 | A/B/C/D |
| TPC-C 事务 | New-Order、Payment、提交、回滚、库存变动日志 | A/B/C |
| 性能分析 | 并发线程、平均延迟、吞吐量、成功失败数、图表 | C/D |
| 报告证据 | 截图、EXPLAIN、行数、导入日志、测试结果 | A/B/C/D |

## 5. 非功能需求

| 类型 | 要求 |
|---|---|
| 可独立开发 | 前端使用 Mock JSON，后端使用 Mock Repository，数据库使用样例数据 |
| 可合并 | 所有跨层字段以 API/Mock 契约为准 |
| 可复现 | Docker PostgreSQL、SQL 执行顺序、正式导入脚本可重复运行 |
| 可解释 | 每个核心查询有 SQL、索引、EXPLAIN 和性能结果 |
| 可演示 | 页面流程连续，错误提示清楚，图表能展示真实或测试数据 |

## 6. 验收指标

```text
后端接口可启动并返回统一响应
前端 Mock 和真实接口两种模式均可演示核心流程
SF=0.1 必须完成导入和查询
SF=0.6/SF=1 用于最终性能测试，按第 4-5 天冻结
至少 4 个 TPC-H 查询
至少 2 个 TPC-C 事务
至少 1 个触发器、1 个存储过程、1 个库存变动日志场景
有索引前后对比和并发性能图表
```
