# TPC CommerceInsight 冻结文档

> 状态：冻结基线  
> 适用对象：A 数据库、B 后端、C 前端、D 环境与性能  
> 冻结目的：让四位成员可以独立开发，并在联调阶段按同一契约合并。

---

## 1. 冻结范围

本项目冻结以下内容：

1. 项目目标、演示范围和验收路径；
2. 仓库目录、分支策略和提交规范；
3. 数据库命名、表结构职责、SQL 资产目录；
4. API 路径、请求响应格式、错误码和 Mock 字段；
5. 开发初始化模式与正式导入模式；
6. 前后端联调、数据库联调和性能测试输入输出；
7. 四位成员的交付物边界。

冻结后，任何跨成员影响的变更必须先改文档，再改代码。

## 2. 角色边界冻结

| 成员 | 冻结职责 | 不承担 |
|---|---|---|
| A | 数据库设计、SQL 源资产、约束、触发器、存储过程、索引初版、清洗规则 | Docker、正式数据导入、后端接口、前端页面、Python 压测 |
| B | SpringBoot 后端、DTO/VO 映射、接口、事务服务、导入导出接口、Mock Repository | Docker、dbgen、前端图表、正式压测 |
| C | Vue 前端、Mock JSON、页面、ECharts、前后端联调、截图 | 数据库字段设计、SQL 优化解释、Docker、压测执行 |
| D | Docker PostgreSQL、正式数据、COPY 导入、EXPLAIN、性能测试、报告总控 | 替 A 改 SQL、替 B 修接口、替 C 做页面 |

关键冻结规则：

```text
A 管数据库字段。
B 管 API 字段映射。
C 只依赖 API 字段。
D 管正式环境和实验数据。
```

## 4. 数据库冻结

数据库对象统一使用小写 `snake_case`，禁止双引号对象名。

应用辅助表冻结为：

```text
app_user
import_task
import_error_log
query_log
transaction_log
performance_result
stock_change_log
```

TPC-C 实现口径冻结：

```text
本项目采用课程最小 TPC-C 实现，只覆盖 New-Order 和 Payment 演示所需字段。
stock 不包含标准 TPC-C 的 s_dist_01~s_dist_10。
order_line.ol_dist_info 由 B 在 Mapper/Service 中传入固定值或按 districtId 生成。
如改为完整 BenchmarkSQL 兼容实现，必须重新评审 A/B/C/D 影响。
```

`stock_change_log` 用于记录 TPC-C 库存变化，至少包含：

```text
log_id
warehouse_id
item_id
old_quantity
new_quantity
change_quantity
change_type
related_transaction_id
changed_at
```

数据库字段与 API 字段映射冻结：

| 层级 | 命名 | 负责人 |
|---|---|---|
| PostgreSQL 表字段 | `snake_case` | A |
| SQL 查询输出别名 | 优先 `snake_case`，由 B 映射 | A/B |
| Java DTO/VO | `lowerCamelCase` | B |
| API JSON | `lowerCamelCase` | B |
| Vue 页面与 Mock | `lowerCamelCase`，只按 API 契约 | C |

A 不因前端字段名直接改数据库字段；C 不依赖数据库字段。

## 5. SQL 执行模式冻结

开发初始化模式：

```text
V1 建 TPC-H 表
V2 建 TPC-C 表
V3 建应用表
V4 加约束
V8 建触发器
V9 建存储过程
V10 建索引
V11 可选样例数据
```

正式导入模式：

```text
V1 建 TPC-H 表
V2 建 TPC-C 表
V3 建应用表
COPY 导入 TPC-H SF=0.1/SF=0.6/SF=1 数据
V4 加约束
V8 建触发器
V9 建存储过程
V10 建索引
行数统计
EXPLAIN ANALYZE
```

`00_run_sql_assets.sh` 冻结要求：

```text
使用 LF 换行
提交前执行 chmod +x db/init/00_run_sql_assets.sh
脚本只引用 /sql/V*.sql
脚本中不写业务 DDL/DML
```

## 6. API 冻结

统一响应：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

分页响应：

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "pageNo": 1,
    "pageSize": 20,
    "total": 0,
    "records": []
  }
}
```

字段来源冻结：

```text
后端接口字段以 docs/api/api-contract.md 为准。
Mock 字段以 docs/api/mock-contract.md 为准。
C 的表格、表单、ECharts 只使用 API/Mock 字段。
D 输出给 C 的性能 JSON/CSV 必须能转换为 mock-contract.md 中的 performance 字段。
```

## 7. 每日计划冻结修订

第 3 天 D 的目标冻结为：

```text
开始 SF=1 数据生成；
确保 SF=0.1 完整导入和行数统计完成；
SF=0.6/SF=1 正式数据在第 4-5 天冻结。
```

这意味着第 3 天不能把“SF=1 完成”作为阻塞其他成员的硬前置。

## 8. 变更流程冻结

跨成员变更按以下顺序：

```text
提出变更
判断影响 A/B/C/D 哪些成员
先更新对应 docs 契约
相关成员确认
再改代码或 SQL
提交 PR
联调验证
合并
```

需要文档确认的变更：

```text
新增/删除表字段
修改 API 路径
修改 API 字段名
修改 Mock 字段
修改 SQL 执行顺序
修改 Docker 数据库连接参数
修改性能结果 JSON/CSV 字段
```
